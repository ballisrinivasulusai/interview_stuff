🟠

MLO (Memory Loader)

First stage bootloader. Loaded directly by the SoC's internal ROM code.

  • Initializes RAM (DDR)
  • Sets up minimal clocks
  • Loads U-Boot into RAM
  • Also called X-Loader on OMAP/AM boards
🟢

U-Boot

Second stage bootloader. Fully-featured, configurable.

  • Initializes all hardware
  • Loads Linux Kernel + DTB into RAM
  • Passes bootargs to kernel
  • Supports UART, SD, NAND boot
🟣

Kernel

Linux OS core. Manages all hardware and system resources.

  • Process management
  • Memory management
  • Device drivers
  • Reads .dtb (Device Tree Binary)
🔴

Root File System (RootFS)

User space environment. Contains everything above the kernel.

  • Libraries (libc, openssl…)
  • Binaries (/bin, /sbin…)
  • Applications
  • Config files
✅ Correct: Your understanding of MLO → U-Boot → Kernel → RootFS is exactly right. MLO is indeed loaded by ROM, and U-Boot does load the kernel and device tree into memory.

📄 What is a .bb (BitBake) File?

A recipe file in Yocto that tells BitBake how to build a package. It declares:

  • SRC_URI — where to fetch the source
  • Patches — fixes/modifications to apply
  • DEPENDS — what packages are needed
  • configure / compile / install tasks

🩹 What is a Patch?

A patch is extra code (a diff) applied on top of original source code.

  • Fix a CVE vulnerability in a library
  • Add a board-specific feature
  • Backport a fix from a newer version
# Apply a patch manually:
patch -p1 < fix_cve.patch

📦 MTD — Memory Technology Device

MTD is a Linux subsystem for raw flash memory (NAND/NOR). It provides partitions in flash, like a partition table for flash storage. Tools: mtdinfo flash_erase nandwrite ubinize

CVE — Common Vulnerabilities and Exposures

🔐 What is CVE?

CVE = Common Vulnerabilities and Exposures

  • A unique ID for a known security issue in software/hardware
  • Format: CVE-YEAR-NUMBER e.g., CVE-2023-52434
  • Tracked in the NVD (National Vulnerability Database)
  • Each CVE has a severity score (CVSS)

🔍 NVD Database

Search CVEs at: nvd.nist.gov

Tells you:

  • Which version is affected
  • What is the fix / patch
  • CVSS severity score (0–10)
  • Reference links to patches

Practical Booting on Board (AM437x)

1

Copy image to SD card

# Copy UBI image to SD card boot partition
cp cnt-fs.ubi /media/zumi/Boot/

# Unmount safely
umount /media/zumi/Boot/
2

Insert SD card & Open minicom

# Open serial terminal to board
sudo minicom

# Turn on board → you'll see MLO → U-Boot messages
# Press any key to enter U-Boot menu
3

U-Boot: 3 commands to flash new image to NAND

# Step 1: Erase NAND memory
nand erase.part rootfs

# Step 2: Copy from SD card to RAM
load mmc 0 ${loadaddr} cnt-fs.ubi

# Step 3: Write from RAM to NAND
nand write ${loadaddr} rootfs ${filesize}
✅ Correct! The 3-step flow: Clear NAND → Copy SD to RAM → Write RAM to NAND is exactly right.
4

Reset / Reboot

# In U-Boot:
reset

# Board reboots from NAND with new image
# Loads: MLO → U-Boot → Kernel → RootFS (new)

📁 .profile — What is it?

.profile is a hidden script in your home directory (~/.profile) that runs automatically when a user logs in or the system boots.

  • Set environment variables (PATH, LD_LIBRARY_PATH)
  • Start a script or program automatically at boot
  • Configure terminal settings
# Example ~/.profile
export PATH=/opt/myapp:$PATH
export LD_LIBRARY_PATH=/opt/mylibs
/opt/myapp/start.sh # auto-start app
✅ Correct: Your understanding of .profile is accurate.

💾 EEPROM on Board Side

EEPROM (Electrically Erasable Programmable Read-Only Memory):

  • Small, non-volatile memory on board
  • Stores board-specific settings (MAC address, serial number, calibration)
  • Can be read and written (unlike ROM)
# Read EEPROM:
cat /sys/bus/i2c/devices/1-0050/eeprom

# or use i2c-tools:
i2cdump -y 1 0x50
✅ Correct: EEPROM is read-only for the OS by default but can be written during provisioning.
